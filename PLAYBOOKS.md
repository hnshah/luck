# Luck Intervention Playbooks

Use these after a Luck assessment. The diagnosis is only useful if it changes the next intervention.

## Solvency

Symptoms:
- A person, team, maintainer, or workflow survives through repeated rescue.
- Demand exists, but capacity is the bottleneck.
- Quality depends on one expert remembering hidden steps.

First fix:
- Remove or automate one recurring rescue point before adding more scope.

Anti-patterns:
- Treating demand as proof the system can scale.
- Adding features while support, review, QA, or operations are underwater.

Next test:
- Track whether support load, manual retries, review time, or operator interventions fall after the fix.

## Demand Coupling

Symptoms:
- The idea is interesting, but repeated pull is weak.
- People praise the concept but do not change behavior, pay, or return.
- The team is optimizing demos, not recurring use.

First fix:
- Narrow to the strongest active pain and test whether users trade time, money, data, or workflow change for it.

Anti-patterns:
- Building the impressive surface before proving urgency.
- Mistaking curiosity for demand.

Next test:
- Run a short demand test with a specific audience and require a real commitment, not positive feedback.

## Adoption Friction

Symptoms:
- The product or workflow works after setup, but people fail before first value.
- Users need docs, handholding, or insider knowledge.
- Examples are generic and the first successful run is not obvious.

First fix:
- Create the shortest first-run path that produces a real result with realistic input.

Anti-patterns:
- Adding more power before making the basic path work.
- Explaining the framework instead of removing the confusing step.

Next test:
- Watch a new user or agent complete the first run without help, then count stalls and time-to-value.

## Compounding Loop

Symptoms:
- Work is high quality but resets every time.
- Runs do not create reusable templates, checks, examples, data, or distribution.
- Lessons stay in one person's head.

First fix:
- Make each successful run produce one reusable asset that improves the next run.

Anti-patterns:
- Shipping outputs without harvesting the learning.
- Calling repetition progress when the system is not getting easier.

Next test:
- Compare the next run against the prior run for speed, quality, reuse, or reduced intervention.

## Circulation

Symptoms:
- Useful knowledge, money, attention, or feedback enters the system and gets stuck.
- Repeated questions happen because answers do not travel.
- A central person manually routes value between nodes.

First fix:
- Create a routing loop: capture, package, publish, and reuse the recurring value.

Anti-patterns:
- Confusing high-quality conversations with institutional memory.
- Letting chat, meetings, or one-off docs become the only storage layer.

Next test:
- Check whether a new person can find and reuse prior knowledge without asking the central operator.

## Integration

Symptoms:
- The thing is useful but lives outside the workflow where decisions happen.
- Users copy/paste, upload files, or manually transfer outputs.
- Usage spikes during demos and fades in real operation.

First fix:
- Connect to the existing system of record or handoff before adding more capability.

Anti-patterns:
- Building a better standalone island.
- Optimizing analysis quality while ignoring where the result must land.

Next test:
- Measure repeat usage after the output appears inside the user's normal workflow.

## Timing

Symptoms:
- The idea is directionally right, but prerequisites are missing.
- Trust, standards, liquidity, infrastructure, or behavior change has not arrived.
- The decision is really about sequence, not whether the idea is good.

First fix:
- Build the prerequisite that makes the larger move viable.

Anti-patterns:
- Launching the final form before the enabling condition exists.
- Waiting passively instead of manufacturing readiness.

Next test:
- Define the threshold that proves the prerequisite exists, then retest the larger move only after that threshold is met.
