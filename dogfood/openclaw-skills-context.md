# OpenClaw Skills Quality Context

## Goal

Make skills consistently improve real agent behavior without bloating context, adding ceremony, or causing agents to recite frameworks.

## Current State

The workspace has many skills for research, strategy, writing, CRO, browser automation, sessions, and operational workflows. Skill files can encode strong domain methods, but quality varies by specificity, trigger clarity, output constraints, and evidence requirements.

## Active Demand

Skills are used in real work for founder strategy, research, session artifacts, CRO audits, model usage, and workflow design. Hiten wants execution quality and speed, not generic theory.

## First-Run Path

An agent sees the skill catalog, chooses a matching skill, reads SKILL.md, follows the workflow, and applies it inside the task.

## Adoption Friction

Agents can over-trigger skills, under-read them, load too much reference material, or treat the skill as content to summarize instead of an operating procedure.

## Maintenance Burden

Skills need pruning, examples, evals, and real-use feedback. Otherwise old instructions drift away from the actual way work gets done.

## Compounding Loop

Every high-quality task should identify which skill behavior helped, which instruction caused friction, and what should be turned into a reusable skill improvement.

## Circulation

Most skill learnings stay in session transcripts or daily memory. They need to flow into skill files, tests, examples, and trigger guidance.

## Integration

Skills integrate directly with OpenClaw/Codex behavior, local scripts, memory files, and project workflows.

## Known Failure

Fragmented ecology: many useful skills exist, but the handoffs between skill choice, task execution, evidence, and improvement are inconsistent.
