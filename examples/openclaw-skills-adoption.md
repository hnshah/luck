# Example: OpenClaw Skills Adoption

## Context

OpenClaw has a large skill library for research, strategy, writing, browser automation, session artifacts, CRO work, and operational workflows. The library is useful, but skill quality depends on agents choosing the right skill, reading the right amount, and applying it as a procedure.

## Luck Assessment: OpenClaw Skills Quality

### Verdict
- Promising but fragile

### Binding Constraint
- Adoption friction: agents can over-trigger skills, under-read them, or summarize them instead of using them to change the work.

### Why
- Demand coupling is strong because skills are used in live work.
- Integration is strong because skills directly shape agent behavior.
- Circulation is weak because task learnings often stay in transcripts or memory instead of flowing back into skill files and examples.
- Adoption friction is weak because trigger rules, evidence requirements, and done criteria vary by skill.

### Failure Mode To Avoid
- Fragmented ecology - many useful skills exist, but the handoff from skill selection to execution to improvement stays inconsistent.

### Next Test
- Run a pilot on real tasks and log where agents over-trigger, under-use, or misapply skills.

### What To Do Now
1. Add a skill-use quality checklist focused on trigger, evidence, execution, and output.
2. Convert repeated task failures into skill edits or examples.
3. Defer adding new skills until the improvement loop works on existing ones.

## Weak Generic Answer

The weak answer would say to write better skill descriptions or add more skills. The real issue is first-use behavior and feedback circulation, not quantity.

## Recheck Criteria

Recheck after several real tasks. The constraint improves if agents use fewer skills more correctly and task outcomes generate specific skill improvements.
